Slide 9 หน้า 1–16 — Full data analysis with auto.arima() and ETS()

Full data analysis: auto.arima, ETS และการเทียบด้วย tsCV

อ่านประมาณ 10 นาที · ข้อความไฮไลต์คือถ้อยคำบนสไลด์ ตัวเลขยก1คือนาทีในคลิปที่รวมไว้ท้ายบท

Lesson 7–9 เลือก p, d, q, P, D, Q ด้วยการดูกราฟและตาราง AIC ซึ่งเป็น "subjective approach" ของสมัยก่อน บทนี้คือวิธีที่ใช้จริงและเป็นแนวของข้อสอบภาคปฏิบัติ auto.arima ค้นหา d, D, p, q, P, Q ให้อัตโนมัติด้วย AICc แต่ช่วยแค่ขั้น 3–5 การแปลงข้อมูลและตรวจ residual ยังต้องทำเอง ETS กับ ARIMA เป็นคนละตระกูล บางคู่เทียบเท่ากัน เช่น ETS(A,N,N) = ARIMA(0,1,1) แต่ห้ามเทียบ AIC ข้ามตระกูล สิ่งที่ใช้เทียบแทนคือ tsCV ซึ่งวัดความแม่นยำของการพยากรณ์ด้วย rolling forecast origin และใช้ได้กับทุกตระกูล

เรื่องที่ระบุว่าเกี่ยวกับข้อสอบในบทนี้มีดังนี้

  • เชื่อม ETS กับ ARIMA เคยออกข้อสอบเก่า1 อย่างน้อยต้องรู้สองแถวบนของตาราง คือ ETS(A,N,N) ↔ ARIMA(0,1,1) และ Holt ↔ ARIMA(0,2,2)
  • ห้ามเทียบ AIC ข้ามตระกูล แม้แต่ AICc2
  • auto.arima ช่วยแค่ step 3, 4, 5 ส่วน transformation และการตรวจ residual ต้องทำเอง3
  • เขียนโมเดลจาก output ของ auto.arima ให้เป็น การบ้านคือเขียน ARIMA(1,0,2)×(0,1,1)₁₂ ของ german เอง4
  • Ljung-Box/portmanteau มี H0 คือโมเดลเหมาะสม p > 0.05 คือผ่าน5
  • ข้อสรุปท้ายคลิปคือใส่ differencing ไว้ใน arima ดีกว่า diff เองก่อน6

1. auto.arima ทำงานอย่างไร และเจ็ดขั้นของการวิเคราะห์

สไลด์ชุดนี้ทำมานานตั้งแต่ยังไม่มีคำสั่ง auto.arima7 วิชาเดิมจบที่ Box-Jenkins แต่เทอมนี้จะมี frequency domain และ ARCH/GARCH ด้วย auto.arima คือเครื่องมือที่ "ช่วยชีวิต" จากการลองผิดลองถูก มันใช้ algorithm ของ Hyndman และ Khandakar (2008) ซึ่งรวมสามอย่าง คือ unit root test เพื่อเลือก d และ D, การหา AICc ต่ำสุดเพื่อเลือก p, q, P, Q และ MLE เพื่อประมาณพารามิเตอร์ AICc คือ AIC ที่ปรับสำหรับข้อมูลน้อย จึงแม่นยำกว่า AIC8

\(\mathrm{AICc}=\mathrm{AIC}+\dfrac{2k(k+1)}{n-k-1}\)

ตัวอย่าง german ในตอน 2 มี AIC = −2.77, k = 5 (φ, θ₁, θ₂, Θ₁ และ σ²) และ n = 118 − 12 = 106 หลัง seasonal difference จึงได้ส่วนเพิ่ม \(2(5)(6)/(106-6)=0.6\) และ AICc = −2.17 ตรงกับ output เมื่อ n ใหญ่ ส่วนเพิ่มเข้าใกล้ศูนย์ AICc จึงเท่ากับ AIC ค่าเริ่มต้นของ auto.arima ใช้การประมาณเพื่อให้เร็ว อาจไม่เจอ AICc ต่ำสุดจริง ถ้าต้องการค้นละเอียดให้ใส่ approximation = FALSE และ stepwise = FALSE

การวิเคราะห์ข้อมูลทั้งชุดมีเจ็ดขั้น9

  1. plot และหาค่าผิดปกติ
  2. ถ้า variance ไม่คงที่ให้ log หรือ Box-Cox ขั้นนี้ auto.arima ไม่ทำให้ ("auto.arima ไม่ transform ให้นะครับ")
  3. difference จนนิ่ง
  4. ดู ACF/PACF
  5. ลองโมเดลด้วย AICc
  6. ตรวจ residual ด้วย ACF และ portmanteau test ขั้นนี้ auto.arima ก็ไม่ทำให้ ("auto.arima ไม่ได้ตรวจสอบ residual ให้")
  7. พยากรณ์

สไลด์สรุปว่า The Hyndman-Khandakar algorithm (auto.arima) only takes care of steps 3–5. ขั้น 3–5 คือส่วนที่ไม่ต้องดูกราฟ ACF/PACF หรือตาราง AIC/BIC เองอีกแล้ว เพราะ auto.arima แนะนำ d และ D ให้10

2. German inflation ด้วย auto.arima

german คืออัตราเงินเฟ้อรายเดือนของเยอรมนี มกราคม 2008 ถึงตุลาคม 2017 รวม 118 ค่า ไม่มี trend มี seasonal และ variance คงที่11 เป็นข้อมูลชุดเดียวกับ Lesson 4 ซึ่ง ETS ได้ ETS(A,N,A) ต้องสร้างด้วย ts(data, start = 2008, frequency = 12) เพื่อให้ R รู้ว่า s = 12 คำสั่ง auto.arima มีอาร์กิวเมนต์สามตัวที่ใช้ทุกครั้ง12

  • stepwise = TRUE ค้นแบบเพิ่มหรือลดอันดับทีละขั้นจากโมเดลปัจจุบัน เร็วกว่า เทียบได้กับ stepwise variable selection ในวิชา regression ถ้า FALSE จะลองทุกโมเดล ใช้เวลานาน โดยเฉพาะ seasonal
  • trace = TRUE แสดงทุกโมเดลที่ลองพร้อม AICc ราว 20–30 โมเดล "ไม่ได้จำเป็นขนาดนั้น แต่อยากให้นิสิตเรียนรู้"
  • approximation = FALSE ถ้า TRUE จะใช้ conditional sum of squares และ AICc แบบประมาณระหว่างค้น (โมเดลสุดท้ายยังใช้ MLE) เหมาะกับข้อมูลยาว 1000–3000 จุด german สั้นจึงตั้ง FALSE

trace แต่ละบรรทัดเขียน ARIMA(p,d,q)(P,D,Q)[12] ตามด้วย AICc วงเล็บแรกคือส่วน non-seasonal วงเล็บหลังคือส่วน seasonal13 บรรทัดที่เป็น Inf คือโมเดลที่ฟิตไม่ได้ เช่น ไม่นิ่ง เมื่อรันจริงได้ ARIMA(1,0,2)(0,1,1)[12] with drift ที่ AICc 0.049 ก่อน แล้วลองตัด drift ได้ −2.166 ต่ำกว่า จึงเลือก ARIMA(1,0,2)(0,1,1)[12] ค่าสัมประสิทธิ์ที่ได้คือ

3. ETS กับ ARIMA: ความเทียบเท่าและข้อห้าม

สไลด์เริ่มด้วยการแก้ความเชื่อผิด It is a commonly held myth that ARIMA models are more general than exponential smoothing. ความจริงคือสองตระกูลซ้อนกันบางส่วน ETS แบบ linear บางตัวเทียบเท่า ARIMA บางตัว ARIMA จำนวนมากไม่มีคู่ใน ETS และ ETS ทุกตัวไม่นิ่ง ขณะที่ ARIMA บางตัวนิ่ง

ตารางบนสไลด์ (R และ Hyndman ใช้ MA แบบบวก) มีสองแถวแรกที่ต้องจำ20 แถวแรกคือผลเดียวกับ Lesson 7 คือ α = 1 + θ ถ้า θ = −0.6 จะได้ α = 0.4 ถ้าโจทย์ใช้ MA แบบลบ \(w_t-\theta w_{t-1}\) จะเป็น α = 1 − θ แถวสองคือ Holt เช่น α = 0.8, β = 0.1 ได้ θ₁ = 0.8 + 0.1 − 2 = −1.1 และ θ₂ = 1 − 0.8 = 0.2 ARIMA ของแถวนี้มี d = 221 ETS แบบ multiplicative (เช่น M,A,M ของ Xbox) ไม่มีคู่ใน ARIMA

4. เทียบโมเดลด้วย tsCV

tsCV สร้าง error ทุกจุดเวลา training set คือข้อมูลทั้งหมดก่อนจุดทดสอบ test set คือหนึ่งค่าถัดไป แล้วเลื่อนจุดเริ่มพยากรณ์ไปเรื่อย ๆ (rolling forecast origin) ความแม่นยำคือค่าเฉลี่ยของ error ทั้งอนุกรม ในคลิปเรียกวิธีนี้ว่า "leave one out cross validation"24 รอบหนึ่งใช้ n − 1 จุดพยากรณ์จุดสุดท้าย รอบสองใช้ n − 2 จุดพยากรณ์จุดถัดไป และฟิตโมเดลใหม่ทุกรอบ จึงรันนาน 5–10 นาที คำว่า leave-one-out ใน cross-sectional หมายถึงตัดจุดใดก็ได้ออก แต่ tsCV ใช้เฉพาะอดีตพยากรณ์อนาคต ซึ่งถูกต้องสำหรับอนุกรมเวลา เพราะในงานจริงไม่มีข้อมูลอนาคตให้ใช้ ตัวอย่าง n = 5 กับ h = 1 ใช้ {1} พยากรณ์ 2, {1, 2} พยากรณ์ 3, {1, 2, 3} พยากรณ์ 4 และ {1, …, 4} พยากรณ์ 5 ได้ error สี่ค่า จุดแรกไม่มี error ใน R จึงเป็น NA และต้องใส่ na.rm = TRUE

โค้ดสร้างฟังก์ชันพยากรณ์สองตัวแล้วส่งให้ tsCV ฟังก์ชันแรก forecastets = function(x, h) forecast(ets(x), h = h) รับข้อมูลช่วง training แล้วคืนค่าพยากรณ์ ซึ่ง tsCV จะเรียกซ้ำทุกจุด ฟังก์ชันที่สอง forecastarima = function(x, h) forecast(auto.arima(x), stepwise = T, approximation = F, h = h) เหมือนกันแต่เลือก ARIMA ใหม่ทุกครั้ง (ในโค้ดของสไลด์ stepwise, approximation ถูกส่งให้ forecast ไม่ใช่ auto.arima จึงไม่มีผล) tsCV(germaninfl, forecastets, h = 1) คืน error ของการพยากรณ์หนึ่งก้าวทุกจุด ซึ่งต้องใช้ h = 125 แล้ว mean(etserror^2, na.rm = TRUE) คือ MSE ที่ข้าม NA

ผลบนสไลด์คือ MSE ETS = 0.09074 และ MSE ARIMA = 0.0770026 ARIMA ต่ำกว่าราว 15% จึงชนะ (รันซ้ำด้วย forecast เวอร์ชันปัจจุบันได้ ETS 0.0863 และ ARIMA 0.0770 ข้อสรุปเหมือนเดิม) RMSE คือ √0.077 = 0.278 เทียบกับ σ̂ = 0.221 ของโมเดลที่ฟิตกับข้อมูลทั้งหมด error นอกตัวอย่างจึงใหญ่กว่าในตัวอย่าง ซึ่งเป็นปกติ

auto.arima ได้ ar1 = −0.3690 (s.e. 0.1763), drift = 0.4904 (s.e. 0.0720), σ² = 0.2779, AIC = 46.1, AICc = 47.14 โดย drift คือ intercept ของผลต่าง28 เขียนได้ \(\nabla X_t-0.4904=-0.369(\nabla X_{t-1}-0.4904)+w_t\) คืออัตราเพิ่มเฉลี่ย 0.49 จุดต่อปี สไลด์แสดงว่าได้ค่าเดียวกับ arima(diff(singapur), order = c(1,0,0)) ที่มี intercept 0.4904 พยากรณ์ 2008–2010 = 84.06, 84.53, 85.03

ETS(M,Ad,N) คือ error คูณ trend บวกแบบ damped ไม่มี seasonal α = 0.528, β = 0.0001, φ = 0.959 (Lesson 4) หรือ double exponential smoothing แบบ damped29 φ ทำให้ค่าพยากรณ์ค่อย ๆ โค้งเข้า เหมาะกับข้อมูลที่มีเพดาน 100

MSE ETS = 0.6198 และ MSE ARIMA = 0.5471 ARIMA ชนะอีกครั้ง30 แต่ข้อมูลมีแค่ 28 ค่า ความต่างนี้จึงไม่แน่นอนนัก และ auto.arima กับ ets ในรอบแรก ๆ ของ tsCV ใช้ข้อมูลเพียงไม่กี่ค่า

สองโมเดลต่างกันมากกว่าที่คลิปบอก ("ต่างกันอยู่นิดนึง") ปีที่สามต่างกัน 1.45 จุด เพราะ Model 1 ไม่มี drift ส่วน Model 2 มี intercept ที่กลายเป็น drift ข้อมูลนี้มี trend ชัด drift จึงสำคัญ แม้แต่ ar1 ยังกลับเครื่องหมาย (0.22 กับ −0.37) เพราะเมื่อไม่มี drift ส่วน AR ต้องพยายามอธิบายการเพิ่มขึ้นแทน วิธีที่ได้ทั้งความสะดวกและ drift คือ Arima(singapur, order = c(1,1,0), include.drift = TRUE) หรือ auto.arima ข้อสรุปท้ายคลิปคือใส่ d ในคำสั่ง32 แต่ต้องตรวจว่าต้องมี drift หรือไม่
